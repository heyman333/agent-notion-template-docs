# Notion 스타일 문서 생성

사용자가 요청하는 모든 문서(HTML, Markdown, artifact)는 아래 규격을 따른다.
근거 템플릿: https://cautious-shovel-8bd.notion.site/3ccb975b320f80128e94c05534b4df9d ("새해 캠페인 제안")

## 1. 문서 구조 (필수)

제목 아래 본문은 이 4단 흐름을 따른다. 문서 성격에 맞게 섹션 **이름은 바꿔도 되지만
흐름(맥락 → 근거 → 판단 → 행동)은 유지**한다. 해당 없는 섹션은 빼도 된다.

| 섹션 | 담는 내용 |
|---|---|
| **배경** | 문서의 맥락, 목표, 범위. 왜 이 문서를 쓰는지 2~4문장 |
| **분석** | 연구 결과, 데이터 인사이트, 주요 고려 사항. 표·차트·코드 근거는 여기 |
| **권장 사항** | 제안된 솔루션, 전략 및 다음 단계. 선택지가 여럿이면 비교표 + 추천 명시 |
| **실행** | 액션 아이템(체크리스트), 타임라인, 리소스 요구 사항, 담당 |

문서 유형별 섹션 이름 예:
- 제안서: 배경 / 분석 / 권장 사항 / 실행
- 장애·버그 보고서: 배경(현상) / 분석(원인) / 권장 사항(수정안) / 실행(조치·재발 방지)
- 기술 검토: 배경 / 분석(비교·측정) / 권장 사항(결론) / 실행(적용 계획)

## 2. 머리 부분 (필수)

1. **페이지 아이콘**: 문서 주제에 맞는 이모지 1개를 제목 위에 크게 (Notion 페이지 아이콘 역할)
2. **제목**: 명사구로 짧게 (예: "새해 캠페인 제안")
3. **메타 줄**: 작성일 · 작성자 · 상태/분류 태그(pill). 태그는 템플릿의 "제안"처럼 1~2개만

## 3. 비주얼 스타일 (HTML)

**HTML 문서는 반드시 이 skill 디렉토리의 `template.html` 스켈레톤에서 시작한다.**
CSS를 새로 짓지 말고 템플릿의 클래스를 그대로 쓴다. 핵심 규칙:

- 본문 폭 708px 중앙 정렬, 여백 넉넉히 — Notion 페이지 그대로
- 글자색 `#37352F`, 배경 흰색, 장식 최소화. 그림자·그라데이션·진한 배경색 금지
- 섹션 제목(h2)은 크고 담백하게, 섹션 사이에는 얇은 구분선
- 강조는 **콜아웃**(이모지 + 옅은 배경 박스)으로 — 색은 회색/파랑/노랑/빨강 4종만
- 표는 얇은 회색 테두리 + 옅은 헤더 배경 (Notion simple table)
- 접을 내용은 `<details>` 토글, 할 일은 체크박스 목록
- 코드는 옅은 베이지 배경(`#F7F6F3`) 블록, 인라인 코드는 붉은 강조

Markdown 문서일 때는 같은 구조로: 이모지+제목(h1), 메타 줄, h2 섹션 4개,
콜아웃은 `> 이모지 **제목** — 내용` 인용구로, 실행 섹션은 `- [ ]` 체크리스트로.

## 4. 문체

- 템플릿처럼 **개조식과 짧은 평서문**을 섞는다. 만연체 금지
- 섹션 도입은 1~2문장으로 그 섹션이 답하는 질문을 말하고, 상세는 목록·표로
- 근거 없는 수식어("혁신적인", "강력한") 대신 수치·파일 경로·명령어를 적는다

## 5. 다른 skill과의 관계

- Artifact로 게시할 때는 규정대로 `artifact-design` 도 로드하되, **구조와 스타일 토큰은
  이 skill 이 우선**한다 (artifact-design 은 반응형·다크모드 등 기술 요건만 가져온다)
- 차트가 들어가면 `dataviz` skill 의 색·마크 규칙을 따르되 레이아웃은 이 템플릿 안에 넣는다
